# 哪些应用/界面可能无法被无障碍服务完整识别

无障碍服务能读到什么，取决于**目标应用有没有把界面暴露成无障碍节点**。下面按"完全读不到 → 部分读不到 → 能读到但语义缺失"分级说明，并给出本应用的应对。

---

## 一、完全读不到（节点树为空）

| 场景 | 原因 | 本应用表现 |
|---|---|---|
| `FLAG_SECURE` 窗口（银行、支付、部分密码页、DRM 视频） | 系统级禁止截屏与无障碍读取，节点为空 | 扫描返回空，不产生记录；**不做任何绕过** |
| 纯 `SurfaceView` / `TextureView` 渲染（视频播放器、相机预览、部分地图） | 内容由 GPU 直接绘制，没有 View 层级 | 只能读到外层容器，读不到画面里的文字 |
| 游戏引擎（Unity / Cocos / UE） | 自绘 Canvas，无标准控件 | 同上 |
| Flutter 应用（部分版本） | 语义树默认不开启，需应用主动启用 semantics | 多数只能读到少量容器节点 |
| 跨进程 Surface（画中画、远程 View） | 无节点可遍历 | 读不到 |

**判定方法**：在「自检」页看「当前可见窗口数」。如果窗口数 > 0 但「扫描次数」增长却没有记录，说明窗口存在但节点树为空——这类界面基本无解，只能靠 OCR（见第四节）。

---

## 二、部分读不到（有节点但缺信息）

| 场景 | 现象 |
|---|---|
| WebView 页面 | 网页控件常暴露为 `android.view.View` 而非 `EditText`/`Button`，`className` 不可靠；文本通常在 `contentDescription` 或虚拟节点里 |
| Compose 界面 | 默认没有 `resource-id`，`viewIdResourceName` 为空；文本节点存在但层级较扁平 |
| 自绘 Dialog（Canvas 画出来的弹窗） | 只有一张整块 View，没有内部控件 |
| 输入法窗口 | 类型为 `TYPE_INPUT_METHOD`，通常不参与业务判断 |
| 通知栏 / 系统弹窗 | 部分节点属于 SystemUI，权限受限 |
| 分屏 / 自由窗口 | 多个窗口同时活跃，弹窗归属判断需要靠窗口边界，可能误判 |

**本应用的应对**：

1. 评分模型里**关键词权重最高**（每个 +3，封顶 9），就是为了在控件类名不可靠时仍能命中；
2. 控件特征（输入框 +2、兑换按钮 +2）只是加分项，不是必需项；
3. 记录里保留「控件类型」字段，便于你判断这次是靠文本命中的还是靠控件命中的。

---

## 三、能读到但语义缺失

| 场景 | 现象 |
|---|---|
| 图片化文案（弹窗标题是 PNG） | 文本节点为空，关键词命中不了 |
| 密码框 | `isPassword=true`，本应用**主动跳过**，不读取文本（设计如此，不可关闭） |
| 加密/混淆的控件树 | 节点存在但 `text` 为占位符 |
| 自定义 View 未实现 `onInitializeAccessibilityNodeInfo` | 只有 className，没有文本与可编辑标记 |

---

## 四、OCR 能补什么、不能补什么

`full` 变体自带 ML Kit 离线文字识别，可用于"节点为空但画面有字"的情况。

- **能补**：自绘弹窗、游戏内公告、Flutter 界面里的文字。
- **不能补**：`FLAG_SECURE` 窗口（截屏本身就被禁止）。
- **前提**：需要在 `accessibility_service_config.xml` 里显式加 `android:canTakeScreenshot="true"`，并接受"服务可截屏"这一隐私面扩大。**本工程默认关闭**，只保留引擎与开关。

---

## 五、系统与厂商限制

| 限制 | 说明 |
|---|---|
| 侧载受限设置（Android 13+） | 未放行前无障碍开关不可用，见 `install-guide.md` 第 4 节 |
| 部分 ROM 的"无障碍快捷方式""后台限制" | 小米/华为/OPPO 等有自有开关，可能需要在电池/后台管理里额外放行 |
| 服务被系统回收 | 长时间空闲可能被解绑；重新开启后自动恢复，不依赖常驻进程 |
| 应用白名单为空 | 白名单模式下若一个都没勾选，则**不监测任何应用**（这是预期行为，避免"以为在监测"） |
| 厂商自研弹窗框架 | 某些 ROM 的应用商店/支付弹窗属于系统进程，包名与业务应用不一致，记录里会显示系统包名 |

---

## 六、怎么快速判断"是不是本应用的问题"

按顺序看「自检」页：

1. **系统已启用 = 是** → 无障碍本身没问题；
2. **进程内已连接 = 是** → 服务没被回收；
3. **可读取窗口内容 = true** → 有读节点的权限；
4. **交互窗口标志 = true** → 能拿到 `getWindows()`；
5. **当前可见窗口数 > 0** → 系统确实返回了窗口。

五项全绿但目标应用仍检测不到，问题就在**目标应用自身不暴露节点**（本文第一、二节），而不是本应用的配置。

## 七、操作边界

**已具备**（2026-11-14 起）：按样例归纳规律批量生成候选，向前台兑换弹窗逐条填入并点击提交，按返回文案判定结果、错误就清空换下一条（`BatchTrialRunner`）。全部通过无障碍 `ACTION_SET_TEXT` / `ACTION_CLICK` 完成。

**仍然不做**：

- 不绕过 `FLAG_SECURE`（读不到就停，不尝试截屏或注入）；
- 不读取密码框内容（`isPassword` 节点整段跳过，不可配置）；
- 不注入手势 / 不模拟触摸事件 / 不 root / 不 hook；
- 不联网：manifest 无 `INTERNET` 权限，命中结果只落本机 Room 库；
- 不绕过验证码；被限流就退避，连续 3 次限流直接停止。
